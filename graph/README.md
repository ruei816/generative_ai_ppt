# Graph 知識關聯層（Graph Layer）

本目錄把 Wiki 中已整理的知識轉成可追溯、可檢查、可重繪的 Graph。Graph 不是取代 Wiki 的另一份文章，而是 Wiki 的「關係索引」：Wiki 說明概念，Graph 說明概念之間如何連接。

## 核心製作流程

1. **需求與範圍**：先確認 Graph 的用途（知識導覽、技術演進、模組架構或簡報敘事），限定主題與受眾。
2. **資料盤點**：從 `raw/` 與 `wiki/` 找出可作為節點的實體，保留來源路徑。
3. **Graph 規劃**：先定義圖形類型、節點類型、關係類型與閱讀方向，不急著畫圖。
4. **建立節點與關係**：先建結構化 `JSON`，每個節點有唯一 ID；每條關係都要有方向、標籤與證據來源。
5. **大綱確認**：檢查節點是否過多、主線是否清楚、是否有孤立節點或沒有證據的連線。必要時先修改 JSON。
6. **Graph 視覺設計**：依用途選擇 Mermaid、流程圖、概念圖或互動式網頁；決定分群、方向、層級、色彩與標籤。
7. **輸出與簡報整合**：產生 `.mmd` / Markdown 圖解，並從 Graph 的主線安排投影片順序。
8. **初版檢查與回修**：逐一檢查文字、箭頭方向、關係語意、來源與版面；回修 JSON 後再重新輸出。

## 本專案檔案

- `schema.md`：節點、關係與證據欄位規範。
- `object-detection-graph.json`：物件偵測主題的結構化 Graph 資料（建議視為唯一資料來源）。
- `object-detection-graph.mmd`：由目前 Graph 主線整理的 Mermaid 概念圖，可直接嵌入 Markdown。

## 維護原則

- **先資料、後視覺**：不要直接在圖片上手動畫關係；先更新 JSON，再更新圖。
- **一條線就是一項主張**：每條 edge 必須能在 Wiki 或 raw 來源找到依據。
- **區分事實與編排**：Graph 的節點與關係是知識內容；群組、位置與閱讀方向是視覺編排，不可混為一談。
- **不確定就不連線**：沒有來源支持的關係先標記待確認，不得由模型自行補足。
- **Graph 與 Wiki 同步**：新增或改名 Wiki 頁面時，檢查 Graph 的節點、邊與連結。
- **簡報從 Graph 取主線**：簡報先沿 Graph 的主路徑安排，再補充分支、比較與限制。

## 建議工作順序

`raw/` → Wiki 梳理 → Graph JSON → Graph 檢查 → Mermaid / 視覺化 → HTML 簡報 → Lint
