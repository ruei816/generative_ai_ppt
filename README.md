# 物件偵測教學簡報：LLM Wiki × Workflow Graph

本專案以 **Object Detection（物件偵測）** 為主題，透過 LLM Wiki 建立主題知識庫，並運用 Graph 規劃整體資料整理、內容設計與簡報製作流程，最後將整理完成的知識轉換成一份可互動瀏覽的 HTML 教學簡報。

本專案除了介紹物件偵測相關技術，也記錄如何運用 LLM 協助資料蒐集、知識整理、流程規劃與教學內容製作。

---

## 一、專案目標

本專案主要分為三個部分：

1. **建立 LLM Wiki**：蒐集物件偵測相關資料，整理成具有主題分類與交叉連結的知識文件。
2. **規劃 Workflow Graph**：將整個專案的執行流程拆分成不同節點，透過連線、判斷與循環呈現工作順序及修正機制。
3. **製作 HTML 教學簡報**：以 Wiki 整理的知識為基礎，製作可以實際瀏覽的教學型簡報。

## 二、專案主題

**Object Detection（物件偵測）**

物件偵測是電腦視覺的重要任務，目標是讓電腦辨識影像中的物件，並找出物件在影像中的位置。

本專案主要介紹以下內容：

- 物件偵測的基本概念與任務流程
- Two-stage Detector 與 One-stage Detector
- R-CNN 系列模型的發展
- YOLOv1 的核心概念與預測方式
- IoU、TP、FP、FN 等評估基礎
- Precision、Recall、AP 與 mAP
- HBB（Horizontal Bounding Box）與 OBB（Oriented Bounding Box）
- Rotated IoU 與 Rotated NMS

## 五、Workflow Graph（工作流程圖）

本專案使用 Graph 規劃整體製作流程，將專案拆分成不同工作節點（Node），並透過連線（Edge）表示工作之間的執行順序與關聯。

Graph 不只是呈現單向的工作流程，也包含判斷節點與回饋循環，讓每個階段都能依照檢查結果進行修改與重新確認。

### 第一階段：前期釐清

1. **需求釐清**：確認專案目的、對象與簡報時間。
2. **資料盤點**：整理文件、圖片、數據與參考來源。
3. **Graph 規劃**：確認圖形類型、節點、關係與閱讀方向。

### 第二階段：內容規劃

4. **建立簡報大綱**：安排章節、主題與內容順序。
5. **逐頁內容規劃**：確認每頁標題、重點、圖表與說明。

透過「大綱確認」判斷內容架構是否合理；若需要修改，則返回簡報大綱重新調整，確認後再進行逐頁內容規劃。

### 第三階段：設計與製作

6. **Graph 視覺設計**：設計流程圖、架構圖與關係圖。
7. **簡報製作**：套用版型、安排圖片與文字。
8. **初版檢查**：檢查內容、邏輯與版面。

### 第四階段：驗收與交付

9. **修正與重新檢查**：若檢查未通過，返回修正流程。
10. **定稿與交付**：確認內容與呈現結果後完成交付。

### Graph 設計特色

- **Node（節點）**：代表每個工作項目。
- **Edge（連線）**：表示工作流程與執行順序。
- **Decision（判斷）**：確認大綱或檢查結果是否通過。
- **Loop（循環）**：未通過時返回前面的步驟修改。
- **Stage（階段）**：將整體工作分成四個階段，方便掌握進度。

簡報內容依照由淺入深的方式安排：

| 單元 | 內容 |
|---|---|

| 模型架構 | Two-stage 與 One-stage Detector |

| 評估指標 | IoU、TP、FP、FN、Precision、Recall、AP、mAP |

- 目錄導覽與頁面切換
- 全螢幕瀏覽
- 鍵盤操作
- 觸控操作
- 簡報閱讀進度顯示
- 淺色與深色主題切換
- 響應式頁面設計

## 七、如何使用

### 1. 下載專案

```bash
git clone https://github.com/ruei816/generative_ai_ppt.git
```

### 2. 進入專案資料夾

```bash
cd generative_ai_ppt
```

### 3. 開啟 HTML 簡報

使用瀏覽器直接開啟：

```text
index.html
```

不需要另外安裝 Python 或 Node.js，即可瀏覽簡報。

> 若簡報使用外部圖片或其他資源，請保留原本的相對資料夾結構，避免資源路徑失效。
